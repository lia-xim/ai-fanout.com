# ai-fanout.com project brief

Updated: 2026-08-24

## Purpose

ai-fanout.com helps a person inspect how one bounded OpenAI web-search run expands a keyword. The free tool reports provider-exposed search queries first and visible source URLs second. The bilingual learning area explains how to interpret those observations and use them for research or SEO without turning every phrase into a thin page.

## Audience

- SEO and AEO practitioners investigating how an AI web-search run frames a topic;
- editors and researchers looking for subquestions and source roles;
- site owners checking citations and content gaps;
- reviewers auditing the evidence, privacy and cost contract.

## Visual thesis

Keep the established Controlled Signal system: dark work surface, cool-white typography, cyan observation states, restrained red limits, ruled registers and the branch-map composition. This product rewrite changes content and information architecture, not the approved visual direction.

## Public architecture

- `/` and `/de/`: overview plus free tool;
- `/methodology` and `/de/methode`: exact method, privacy, cost and evidence limits;
- `/library/...` and `/de/lernen/...`: eight paired, intent-distinct guides per language;
- `/transparency`, `/impressum`, `/datenschutz`: ownership, sources, rights and actual processing.

Manual answer comparison, protocol planning, research and dataset routes are no longer public product areas. They remain noindex and excluded from the sitemap while their final removal or archival response is evaluated.

## Evidence boundary

“Observed query” means a query string present in a web-search action returned by the selected API route. No response field means no query. The site does not inspect a consumer UI or claim access to hidden queries, chain of thought, every internal retrieval action, ranking systems, search volume, or other providers.

OpenRouter documents native web search but exact query-string preservation on `openai/gpt-5.2` is still NOT PROVEN without a live authorized fixture. This blocks endpoint enablement, not publication of the learning area.

## Launch gates

- server-only OpenRouter key, Turnstile secret, high-entropy salt and atomic Redis credentials;
- public Turnstile site key and explicit public enable flags;
- live proof of query fields for the selected route;
- adversarial verification of CAPTCHA, five-per-IP and 40/day limits, parallel budget enforcement, timeout, provider errors and no secret leakage;
- privacy copy rechecked against the live configuration.
